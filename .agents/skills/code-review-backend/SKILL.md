# TSZ Rust 后端代码审查

## 范围与证据

- 读取所选 checkout 的 `AGENTS.md`、受影响目录规范、Cargo/CI/hooks 及必要设计，依据当前实现，不把历史部署记录当现状。本文路径相对于所选仓库根目录；技能链接相对于本文件。
- 固定根目录、HEAD、基线和脏状态。用户指定范围优先；未指定且有改动时检查 staged、unstaged、非忽略 untracked 及其最终合成行为。
- 干净任务分支默认审查与 `origin/main` 的 merge-base 到 HEAD 的完整差异；指定 PR 则使用实际 base/head。需要最新引用先 fetch 并记录 SHA/merge-base，失败说明时效局限，不拿空 diff 当完整 PR 通过。审查本身不创建或切换分支；实施新任务时从最新 origin/main 创建独立任务分支和 worktree。
- 提交/PR 用对应 Git 对象读取实现和调用链，不把脏工作区代码或测试结果归属于纯 SHA；跨仓先固定实际 checkout，不凭相邻目录默认配对。
- 沿 handler → DTO → service → repository → 数据约束与调用方追踪，仅展开 diff 实际涉及的风险。

## 按变化选择检查

### API、鉴权与契约

- Axum 路由、extractor、中间件和业务层的角色/资源归属授权是否完整；检查越权读写、批量接口绕过和列表范围泄露，而非仅确认有登录校验。
- DTO/Serde 校验、必填/可选/null、枚举、未知字段、大小/长度限制、分页上限、HTTP 状态码与 Problem Details 是否符合实际消费者。
- cookie/token 的 scope、refresh 轮换/重放/撤销、并发刷新、失败清理与日志脱敏；生产 COOKIE_SECURE 不得因开发配置变化失效。
- API 变化只读参考 [contract-sync](../contract-sync/SKILL.md)：实现/序列化 → `docs/openapi.json` → 选定前端 endpoint/runtime 快照 → wire 类型和调用者。不要运行导出/同步生成器。
- V3 admin 严格 runtime validator 可能拒绝新增响应字段，不能默认「字段只增不减就兼容」。核对旧前端+新后端、新前端+旧后端与目标组合；发布顺序来自实际验证，不一律前端先发。缺配套源码/版本时标记未验证。

### SQLx、迁移与数据完整性

- SQL 参数绑定、动态排序/标识符白名单、条件覆盖与分页稳定性；关注越权、注入、遗漏软删除/范围条件和无界查询。
- 多步写入的事务边界与失败原子性；先查后写竞态是否由唯一约束/锁/条件更新兜底，冲突映射是否正确；重试是否产生重复副作用。
- 外键、唯一约束、级联删除、关联实体身份、历史 null/重复数据与回填；对词条/词形/义项/例句等关系沿当前数据模型核实，不以展示文本代替稳定 ID。
- 迁移 up/down、排序、不可逆数据损失、锁表与旧数据可执行性；检查旧二进制+新 schema、新二进制+旧 schema 的支持/禁止路径及回退限制，不能只证明新版本跑通。
- `.sqlx` 与变更 SQL/schema 的一致性，相关 query/feature 是否实际编译覆盖。缺缓存或缺 DB 只说明阻塞，不能自动 prepare、改连接或在共享库试迁移。

### 并发、缓存与外部 IO

- Tokio 中阻塞调用、跨 await 持锁、无界任务/队列、取消与资源释放；只有可达调用和合理负载证据才判性能缺陷。
- Redis key 的用户/租户/业务维度、TTL、失效顺序、原子操作、锁过期/所有权、故障 fallback；检查缓存与数据库提交顺序及并发一致性。
- OTP、session 等敏感状态的限流、一次性消费、失败计数及重放风险；只审查本次命中的链路。
- speech、对象存储及其他外部服务：超时、重试边界、幂等、请求体/下载上限、URL/路径信任边界、供应商失败映射、凭据脱敏与部分成功残留。
- 涉及发音/音频配置时检查 locale/voice/格式等实际契约和消费者，不把供应商返回成功等同于可播放、可用或已保存。

## 最小验证与交付

- 按当前 Cargo、CI、hooks 和邻近测试选择已有单元、handler、repository 或序列化测试；参考 [build 的验证规则](../build/SKILL.md)，但不进入其实施/生成阶段。
- 可用 `cargo fmt --all -- --check` 检查格式；Rust 定向测试的 target、feature、SQLX_OFFLINE 等取自实际配置，不照搬前端命令。复用有效证据，不因审查再全量 clippy/test/check。
- 新增测试 target 核对是否进入当前 CI 分区清单；关键失败/权限/并发测试检查公开行为与真实约束，不能只看 happy path 或弱断言。
- 执行数据库/Redis 测试前核实连接解析、fallback 和隔离；不读取输出秘密值。不裸 cargo run（服务启动可能迁移）、不迁移共享库、不清库/FLUSHDB、不调用真实付费供应商。隔离不明就报告未验证。
- 默认不改源码/测试、不生成 OpenAPI/.sqlx、不改索引/分支、不提交推送或部署。只读是行为约束而非沙箱；本 Skill 不启动 backend_deploy_runner，也不取代 ship 的独立 reviewer 门禁。当前会话自审如实标注。
- 输出按 P0（紧急广泛事故）/P1（严重关键故障）/P2（实质缺陷）/P3（低影响确定缺陷）排序。每条给仓库/文件:行号、具体输入/前置、影响、调用链/约束/测试证据和最小修复方向。先找反证、合并同根因，不报纯风格或臆测。
- 结尾给审查版本、实际命令与结果、未运行项、迁移/兼容性证据缺口；没有确定发现写「未发现可确认缺陷」。环境阻塞不是代码错误，未执行不能写通过。
