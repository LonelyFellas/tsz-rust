# 后端 Bug：先复现，再修复

本文件是 Claude Code 下后端 bugfix 的**唯一**流程来源。项目约定读 `AGENTS.md`。
**本技能不提交、不推送、不部署。**

修复请求授权必要的本地诊断、测试与最小代码修改；提交、推送、部署按用户已给出的范围判断。
保留用户改动与现场；日志不暴露凭据、token 或整份 `.env`。
Bug 默认不走新功能评估——确实需要新增能力时先说明范围变化。

## 1. 先分清是代码问题还是版本/环境问题

跨前后端的现象**先核对版本**：两仓 checkout、SHA、脏改动、部署版本、feature flag、数据条件。
本项目大量"bug"实为：测试服未开某个 flag、前端快照未同步、部署的不是预期 SHA。
**checkout 更新不证明运行中的进程已加载新代码**——绑不上构建与提交就标记「版本未知」。

## 2. 建立失败基线

**先记录四项**：前置条件、最短命令、预期结果、实际异常。

选成本最低且能证明同一因果链的方法，优先级从高到低：
已有测试 → 新 `#[sqlx::test]` 回归用例 → 直接调 service/repository 函数 →
只读 HTTP 请求打真实端点 → 必要时才走前端 UI。

确定性失败的测试可直接作为基线；时序/并发问题保留多次运行证据，
不用机械次数代替稳定性判断。**复现命中核心异常后保存关键输出并告知用户，再动业务逻辑。**

允许加诊断测试、fixture、临时探针；**不以改业务逻辑试运气**，
不把已有绿色测试或静态猜测称为"已复现"。
数据库诊断只在隔离库上做，**不 TRUNCATE / FLUSHDB / 清空共享库**。

## 3. 无法复现时继续取证

暂不改业务代码。对比精确版本、原始响应体、权限、缓存、数据形状与时序。
大范围翻代码派 [rust-scout](../../agents/rust-scout.md)；接口行为存疑派 [contract-auditor](../../agents/contract-auditor.md)。
能独立完成的只读调查继续做，只有拿不到的环境信息或必要授权才问用户。
报告已排除项、证据缺口和最小下一步，**不把不确定原因包装成修复完成**。

## 4. 定位并最小修复

沿调用链找到规则所属层：handler（状态码/校验）、DTO（形状）、service（业务规则）、
repository（查询/事务/约束）、迁移（数据约束本身）。

区分根因和表面症状，**只改根因及其直接调用点**。涉及 API 时同步 OpenAPI、`.sqlx`、
必要的 fixture，并检查新旧兼容：
**响应新增字段会被前端 V3 runtime validator 拒绝**，这类修复要连带确认发布顺序。

破坏性迁移、公开行为改变或额外系统修改超出原请求时，先说明方案再确认。

## 5. 沿原路径回归

1. **用第 2 步相同的输入和前置条件重跑失败路径**，证明结果恢复预期。
2. 再跑受影响的 `--lib` / `--test <target>` 与契约检查。
3. 清掉临时探针，留下有价值的回归测试；新增 target 记得登记 CI 分区清单。

完整 fmt/clippy/test 三件套接近完成时统一跑一次。
**不得弱化断言、降低门槛或绕过 hooks。**

交付复现证据、根因、最小修复、同路径验证结果、迁移/契约影响和工作区状态。
用户已要求交付时再进入 [ship](../ship/SKILL.md)——建议开新会话做审查。
