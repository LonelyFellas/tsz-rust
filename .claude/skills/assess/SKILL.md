# 后端评估：定档 → 调研 → spec → 交接

本文件是 Claude Code 下后端 assess 的**唯一**流程来源，自带完整规则。
项目约定读 `AGENTS.md` 与仓库文档。**本技能不写实现代码、不跑迁移、不改数据库。**

## 1. 先定档

| 档位     | 判据                                                                             | 产出                                        |
| -------- | -------------------------------------------------------------------------------- | ------------------------------------------- |
| **跳过** | 一句话能说清 diff：改日志、重命名、补一条断言、调整错误文案                      | 不写文档，直接进 [build](../build/SKILL.md) |
| **轻档** | 单模块内、不动 DTO / 迁移 / OpenAPI / 权限                                       | 一份 `design.md`，**≤80 行**                |
| **重档** | API 契约变更、数据库迁移、跨模块、鉴权/权限、数据约束变化、**需要前端配套发布**  | `requirements.md` + `design.md`             |

混合按最重的部分定档。定完档一句话说明档位和理由再往下走。
**只要改动会被前端看到，就是重档**——后端"只是加个字段"在这个项目里不是小事，见第 3 节。

## 2. 调研派子代理

代码调研派 [rust-scout](../../agents/rust-scout.md)，主上下文只接收结论。
一次把问题打包给它：已有能力在哪一层、可复用什么、要改哪些文件、调用链波及哪些端点和测试、
是否需要迁移。

**涉及 API/DTO 的一律另派 [contract-auditor](../../agents/contract-auditor.md)**，
它会跨两仓核对前端消费者与发布顺序。重档可以两个子代理并行派出。

不要在主上下文里 grep 整个 `src/`——这是评估阶段上下文膨胀的主因。

## 3. spec 必须写清发布顺序

写入 `docs/features/<slug>/`；跨仓功能的 spec 集中在任务主仓（通常是前端 tsz），本仓引用即可。

`design.md` 除常规内容（要改的文件与签名、范围外、方案与被否决方案、风险与回退）外，
**后端必须额外写清三件事**：

1. **迁移** —— up/down 成对、执行顺序、对历史数据的影响、能否回退。
2. **契约影响** —— 哪些 method/path 的请求或响应形状变了，字段的必填/可选/nullable/枚举变化。
3. **发布顺序** —— 这是最容易错的一条：
   - **响应新增字段 → 前端先部署**（前端 V3 runtime validator 对未声明字段是拒绝的，
     后端先上会直接打挂旧前端）。
   - **改必填 / 移除字段 / 收窄枚举 → 后端先部署**。
   - 拿不准就写「同批发布」并说明理由，不要赌。

结论以 contract-auditor 的核对为准，不要凭"新增字段应该安全"下判断。

## 4. 验收必须可执行

`design.md` 最后一节是「验收」，内容为**能直接执行的命令**及通过时的预期输出：

```
cargo test --locked --all-features --test lexicon_handler <case_name>
# 预期：新增用例全绿，覆盖 <spec 第 X 条验收标准>
```

需要数据库的集成测试先说明依赖的隔离数据条件。
写不出可跑命令的验收标准，退回去写成可验证的，或明确标注「只能人工验收」并给出步骤与判据。

## 5. 确认与交接

档位、spec、迁移与发布顺序、验收命令一起展示，等用户确认。
本会话已有明确方案批准时沿用授权，不重复问。

确认后**不要接着实现**——请用户开新会话跑 [build](../build/SKILL.md)，
给出开场提示词：`按 docs/features/<slug>/design.md 实现，验收命令是 <cmd>`。
汇报档位、slug、spec 路径、验收命令、发布顺序结论与未决问题。
