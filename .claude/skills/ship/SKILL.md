# 后端交付：Claude Code 适配

执行前读取 [项目 ship 技能](../../../.agents/skills/ship/SKILL.md) 及其要求的引用。
通用授权、分支、检查、提交、推送和 PR 流程只在该文件维护；已加载时直接沿用。本入口只适配其第 4 节的独立审查，不重复自检或另跑全量门。

## 独立审查工具

提交并固定 `review_base_sha` / `review_sha` 后，使用实际可调用的 `/code-review` 审查完整提交范围，给原目标、精确 SHA、项目规则与已有验证，不传自审结论。
`/code-review` 必跑，其独立审查满足项目门禁，不再额外派 reviewer；若工具不可用，报告阻塞，不能虚构调用或用自审替代。

每次显式带 effort，混合改动按最重风险选择，避免沿用上一次档位：

| 改动                                                           | 调用                  |
| -------------------------------------------------------------- | --------------------- |
| 纯文档/注释/日志文案/测试断言，增删合计约 80 行以内            | `/code-review low`    |
| 一般 handler/service 逻辑，不动契约与数据约束                  | `/code-review medium` |
| 迁移/数据约束、鉴权/权限、API 契约、事务/并发、删端点/下线链路 | `/code-review xhigh`  |

可以后台启动审查，同时只补尚缺的受影响验证，汇总真实结果后再继续；已有同状态检查不重跑。
P0–P2 或其他实质正确性/安全问题阻断 push，风格建议不阻断。修复后保留旧/新 SHA，定向验证并只复查 `old_sha..new_sha` 与原问题；范围扩大或初审假设失效才重审全范围。
最终结论必须覆盖当前提交；审查不得用脏工作区替代提交对象，也不重跑已有有效全量检查。之后按项目 ship 继续正常 hooks、推送和 PR，到用户约定终点交付。
