## 目标与范围

让已登录、可正常操作的 C 端用户更换头像，保存成功后更新资料页和账户头像，刷新及重新登录后仍显示新图片。

范围包括上传许可、文件校验和处理、确认、图片读取、替换及账号注销后的清理。保留现有上传交互和数据形状；不顺带实现昵称修改、学习设置、裁剪编辑器、相册、头像删除按钮或管理端上传功能。

## 已确认的产品规则

- 用户已选择头像公开展示：知道图片链接的人可查看已确认的头像，无需登录。
- 原始上传文件仍为私有对象；只有通过校验及处理后的头像能被公开读取。
- 输入格式沿用前端：JPG、PNG、WebP；文件非空，最多 5 MiB。原文件名不作为对象键。
- 后端推荐输出 512×512 静态 WebP，先应用可识别的图片方向，再居中裁切、缩放，并去除原文件元数据。不提供动画展示；格式无法安全解码时明确拒绝。
- 无头像时继续返回 `avatar_url: ""`，使用现有文字头像，不更改 User wire 字段。

## 行为与安全要求

1. 两条写接口仅接受 Web realm 的有效登录身份；学生、教师使用同一规则，不能操作他人的头像。
2. 上传许可绑定用户、服务端生成的 key、类型、精确字节数及到期时间。确认不能只验证 key 前缀，必须核对数据库归属。
3. 过期且未成功的许可重新申请；他人 key、未知 key 的错误不可用于探测他人文件。
4. 后端确认以实际读取的字节为准：检查大小、真实格式、解码及资源上限，不只相信 MIME 或 OSS 元数据。
5. 预签名许可只可写临时对象，不能修改已公开的正式头像；确认后的头像使用新版本地址。
6. 用户头像字段仅在完整确认事务成功后更新。上传、处理、对象写入或数据库失败时，原头像保持不变。
7. 同一许可重复确认可安全重试；旧许可重试不能覆盖后来成功设置的头像。并发确认只能产生一个生效结果。
8. 公开读接口只服务已确认、仍被存在的用户使用的图片，不接受客户端提供的存储路径；未知及非公开对象返回 404。
9. 替换和注销后，旧图片在源站不可再公开读取；文件通过持久清理任务回收。账号删除不能把待清理的对象键随 FK cascade 一起丢掉。
10. 原图清理至少等到预签名到期及短宽限后进行，避免有效上传链接重新写回已删文件；失败需要可重试记录，不能仅 best-effort。
11. 公开图片缓存建议最多 5 分钟。已被下载的图片不能追溯收回，注销后第三方缓存也不承诺即时清除。
12. 限制发放频率和未结束许可数量；图像处理有并发及内存上限，不持有数据库事务等待存储 I/O 或图片处理。
13. 未配置头像存储时明确返回 501，存储故障与输入错误分别表达；签名 URL、headers 和图片内容不进入业务日志。

## 前端配合边界

- 保留现有两条写请求及 `{ upload }`、`{ user }` 响应，PUT 继续使用服务端返回的 URL 与 headers。
- `GET /auth/me` 保留扁平 UserProfile；不为头像改成另一种 me 响应形状。
- `avatar_url` 为可直接用于 `<img>` 的稳定、版本化绝对地址，不使用短期签名 URL 作为长期资料字段。
- 实现后同步 OpenAPI，移除已实现头像端点的 PENDING 白名单，补稳定错误码对应的中文提示。其余未实现资料端点不一并移除白名单。

## 验收标准

- 手机和邮箱账号均能上传三种有效图片；确认、刷新、重新登录后头像一致。
- 错误类型、超大、空文件、损坏图片、过大解码资源和跨用户 key 均拒绝，且旧头像未变。
- 匿名/Admin realm 不能写；公开图片无需 bearer；临时文件和未确认图片不可公开获取。
- 重试、并发、故障补偿、有效签名到期前重传、替换及注销有真实数据库测试覆盖。
- 浏览器验证 OSS PUT CORS、真实 headers、版本缓存和错误提示；单测成功不能代替真实存储验收。
- 上述是实现后的验收要求。本次只验证存储底座的 8 个库单元测试通过，未实施新功能、迁移或真实 OSS 验收。

具体接口、迁移、发布顺序及验收命令见 [设计评估](design.md)。
