# 智能词库架构重构：已确认需求

状态：用户已授权按五批方案实施；尚未授权提交、推送、部署。
基线：origin/main `72747b6186562ecf87ac2984a2d1824f6c50fc9e`。

## 边界

- 尚未正式上线，已有环境数据均为可清除的测试数据。不为旧数据、旧接口增加兼容代码或迁移适配层。
- 破坏性契约调整直接同步前后端。测试数据重置需求单列；不自动连接或清除远端数据库。
- 保留业务正确性、稳定节点身份、乐观并发、发布幂等和事务原子性；不以“无需兼容”作为移除这些保护的理由。
- 维持模块化单体，不引入微服务、通用工作流引擎、图数据库或分布式锁。

## 已确认决策

1. 共享例句独立编辑、独立发布；所有引用方跟随已发布版本，保留历史供回退。
2. 词义草稿可编辑。修正文案保留身份；删除、合并或实质改变含义必须处理引用影响后才能发布，实质不同的词义使用新 ID。
3. 编辑与发布权限分离；不强制双人审核，有发布权限的人可以发布自己编辑的内容。
4. 单独发布要求具体引用目标已发布且有效；用户显式选择的批次支持循环依赖，校验和提交全部成功或全部失败，不递归扩大范围。
5. 回退把历史内容重新发布成新版本，通过当前校验，不覆盖正在编辑的草稿。
6. 从当前词义移除共享例句随宿主词条发布生效；全局下架独立生效，要求发布权限、原因和影响确认，保留引用和历史，普通展示不再使用。
7. 关联候选默认已发布；草稿候选主动展开，标明具体未发布依赖。词条曾发布不代表新增词义已发布。
8. 并发编辑不静默覆盖。保留未保存内容，展示差异，用户调整后基于最新版本重新提交；暂不自动合并或采用字段级版本。
9. 同形词默认复用已有词条；显式确认并提供区分说明后可新建。引用绑定稳定 ID，不按拼写自动合并。
10. 统一完整内部内容模型，逐步替换旧模型转换与字段补回；不只改名，不保留双版本分流。
11. 统一引用规则和影响分析；不同引用保留各自业务结构，不强制统一成一张表。
12. 搜索弱一致，不因无关更新失效；稳定排序和游标尽量减少重复遗漏，保存和发布严格验证。分页不再依赖 outbox 行数。
13. 用针对性验证决定性能投入。优化锁顺序、持锁时间、列表批量查询；仅安全的临时数据库冲突可有限重试，不能重试绕过版本冲突。
14. 草稿、当前发布、保留历史及需要回放的学习记录都保护音频引用。无引用且过宽限期，删除前再次确认；缺失不得静默替换。

## 验收原则

- 每批交付对应的自动验证和必要的前端配套，不把正确性测试留到最后。
- 每批允许多个小改动，不能把中间片段标成整批完成。
- 现有回归用于保护保留的业务行为；与本需求冲突的旧断言应连同实现明确替换，不加兼容分支让两者同时成立。
- 数据库验证只使用已确认的本地隔离环境；未运行的项目必须明示。
- 本文记录目标规则，不声明当前系统已实现。
