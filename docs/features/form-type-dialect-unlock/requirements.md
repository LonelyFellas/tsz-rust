## 1. 需求原文（截图 + 描述）

> **为什么关联单词后，还可以更改词型的类型？**
>
> 目前状态是，关联单词后，引用了的词形的相关参数就会锁定。但是从实际业务逻辑层面，
> 这种锁定是不必要的。词形变化在"英美是否通用"这个层面，有三种情况：
> 1. 英美通用；
> 2. 仅音标有区别，而拼写通用；
> 3. 拼写和音标都有区别。
>
> 无论从哪种情况向另一种情况转换，业务逻辑层面都说得通：
> - 从 1 到 2：音频本就是英美分开存储的，音标出现区别后各读各的音标生成音频；
>   英美界面切换时拼写共用，没有区别。
> - 从 1 到 3：拼写和音标都变化，各自界面显示各自拼写。
> - 从 2 到 3：拼写变化，各自界面显示各自拼写。
>
> 综上所述，只需要调用当前合适的拼写和音标即可，不会在业务逻辑上发生错乱。
> **因此锁定"拼写"和"音标"是不必要的，只是不能删除该词形而已。**

截图标注：「英美拼写是否有区别」勾选时提示「被 1 处引用，需先解除引用」；
「词形类型」下拉被引用后禁用。

## 2. 现状：为什么会被锁（技术根因）

引用在底层绑定的是**具体节点实例 id**（`target_variant_id` / `target_form_id`），
而结构变更会换掉这些 id，于是引用被判失效（stale），保存返回 409，前端索性不让点。

| 层 | 现状 | 位置 |
|---|---|---|
| 引用判定（例句） | `id == link.target_variant_id` 硬相等 + 拼写归一匹配 | `src/lexicon/service/text_links.rs:495 shared_target_matches` |
| 引用判定（成分） | `form.id == target_form_id` 且 `form.form_type == target_form_type` 且变体 id 相等 | `src/lexicon/service/v3.rs:2924 phrase_component_matches_target` |
| 保存守卫 | 对新破坏的引用返回 409 `InboundReferenceConflict` | `src/lexicon/service/inbound_references.rs:672 ensure_inbound_references` |
| 前端锁定（英美） | `split` / `merge` 计数 > 0 即禁用开关 | `referenceGuard.ts:208 dialectRuleLocks`、`V3PosTab.tsx:151` |
| 前端锁定（词形类型/删除） | `formReferenceCount > 0` 禁用类型下拉与删除 | `referenceGuard.ts:150`、`V3FormGroupCard.tsx:264` |

判定在 baseline 上先跑一遍，只拦「本次新破坏」的引用（`v3.rs:1858` 传 `Some((&current_forms, &saved_meanings))`），
已 stale 的旧引用不重复拦截。

## 3. 业界口径（产品未定时的依据）

这类"词形/词条 + 引用"系统（术语库、CMS 节点引用、i18n 内容引用）的通行原则：

> **引用绑定「稳定身份 + 语义坐标」，绝不绑定「会随展示/结构变化的实例编号」。**

- **多区域内容引用**是成熟范式：引用多语言文案时记 `(内容id, locale)`，不记"英文那条记录的 id"。
  语言结构从单一拆成多语、或合并回去，引用自动重解析。
- **词形变化（inflection）在词典/术语系统里属于语义身份的一部分**：`run` 与 `ran` 是两个不同词形，
  例句标注不可自动迁移；因此**改类型应视为「换词形」**，业界不硬锁编辑，但保护引用不被静默破坏。

### 3.1 本需求口径（用户 2026-09-XX 定盘）

| # | 子问题 | 决定 |
|---|---|---|
| ① | 英美结构切换（"英美拼写/音标是否有区别"） | **解锁**。引用改绑「词形 + 方言」语义坐标，通用↔英/美任意切换，引用自动跟随 |
| ② | 词形类型变更（原形→过去式…） | **保护式放开**。允许改；有引用时提示「会让 N 处引用失效」，用户确认后放行 |
| ③ | 删除词形 | **维持锁定**。有引用不许删（需求原文 + 数据完整性） |

## 4. 范围边界

### 4.1 属于本次

- 英美结构切换解锁（①②中的 B）：引用判定改语义坐标 + 变体 id 迁移 + 前端解锁。
- 词形类型保护式放开（②中的 A）：允许改类型，引用侧确认放行，删除仍锁。

### 4.2 明确不改（防止扩大范围）

- **拼写一致性校验**（`spellingConflictReferences`）：例句标注片段与变体拼写归一后对不上，
  仍应拦截——这是数据自洽底线，不随解锁放宽。
- **发音合并冲突**（`pronunciation_merge_required`）、**规则变化一致性**（`regularity_merge_required`）、
  **成分合并冲突**（`component_merge_required`）：维持拦截，结构切换不能静默丢数据。
- **词义级引用**（`publication_sense_ref` / `draft_relation`）：只绑 `sense_id`，不涉及词形，不受影响。
- **已发布快照**：历史发布的引用是冻结的不可变快照，本次判定改造不得影响其解析。

## 5. 验收标准（详见 design.md §6）

后端集成测试（`tests/lexicon_handler.rs`）：

1. 词形被例句标注引用时，切换英美拼写/音标结构 → 保存成功，引用仍成立（不 stale）。
2. 词形被短语成分引用时，同上。
3. 三种结构互转（1↔2、1↔3、2↔3）后，`GET inbound-references` 返回的引用 `stale = false`。
4. 改词形类型：有引用时返回可确认冲突（非硬 409），带 `N` 计数与确认 token；
   确认后保存成功，引用按 ② 的语义处理。
5. 删除被引用的词形 → 仍 409，且引用计数正确。
6. 拼写改到与标注片段对不上 → 仍被拼写一致性校验拦截。
7. 存量数据（旧 id 绑定引用）在新判定下双向兼容——id 相等快速路径命中的引用行为不变。
8. 幂等：同一结构切换保存两次，引用 stale 结果稳定。

前端（Vitest）：

9. 被引用时英美开关可点，不再出现「需先解除引用」置灰。
10. 被引用时词形类型可改，提示「会让 N 处引用失效」并可确认。
11. 删除被引用词形仍禁用，提示保留。
