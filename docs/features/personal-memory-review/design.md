**跨词单个人记忆、错题重测与到期复习设计**

设计日期：2026-10-23；实施验收日期：2026-10-24。状态：三阶段已完成本地实现与验证，未提交、推送或部署。本文件是跨仓任务唯一主记录。用户先确认首期保持原奖励规则、独立复习和错题重测暂不计奖，随后授权完成个人记忆基础、复习接口及前端真实验收三阶段；不提交、不推送、不部署的边界继续有效。调度参数沿用定稿默认值，长期学习效果与生产容量仍需上线后测量。详细结果见第16节。

**1. 目标与现有约束**

目标是让用户换一本词单仍能复用已经形成的记忆，让错题得到再次练习，并由服务端安排到期复习。成功标准包括：同一义项不因换任务而重复建立记忆；刚看过答案后的答对不被当成长时记忆；现有任务仍按原规则完成；重复提交、跨日及多设备不重复推进或发奖；内容失权后不从记忆快照继续传播。

架构审查基线为后端 `feb67318`、前端 `215509ae`。实施前复用两个 `smart-lexicon-architecture-audit` 工作区并快进至后端 `72ff5b6`、前端 `39f78ef6`；本次实现和验收对应这两个基线加未提交改动，不代表已部署版本。

已核实的现状：

| 已有能力 | 本设计的兼容要求 |
| --- | --- |
| 学习单元为 `entry_id:pos_id:sense_id`；当前题型为 `spelling_zh_to_en` | 复用语义身份，首期只建设这一种能力的记忆 |
| 固定批次全部有效首答即完成，答错也计覆盖，正确率另算 | 不把错题重测追加成原任务的完成门槛 |
| coverage 轮次跨日保留已覆盖部分 | 不用个人记忆回写、跳过或代替现有覆盖事实 |
| 答案、完成、奖励在现有事务内提交 | 记忆不能先于答案落库，也不能吞掉原事务技术失败 |
| 每日奖励按当日已完成每日任务的去重单元计算，长期任务不计 | 首期记忆与独立复习不产生新的奖励完成事实 |
| 已确认的政策口径是 10 个去重单元／5 币；登录另为 1 币 | 金额仍以服务端政策为准；本设计不修改配置，不声称线上已启用 |
| Asia/Shanghai 04:00 为任务和奖励业务日边界 | 金币与短测次数预算沿用该日界线；记忆间隔按真实时间计算 |
| 严格响应校验会拒绝未知字段 | 新能力使用独立响应，不向旧 LearningRun/Receipt 等直接加字段 |

**2. 三种事实分开维护**

| 事实 | 回答的问题 | 例子 |
| --- | --- | --- |
| 任务覆盖 | 规定内容是否完成首次有效作答 | 10 题全部提交，答对 7 题：任务完成、正确率 70% |
| 个人记忆 | 这个义项的这项能力最近表现如何，何时再测 | 3 个错误进入待巩固，其余按间隔安排 |
| 奖励资格 | 当天哪些既有每日完成事实满足已批准政策 | 达到 10 个去重单元时最多按政策发一次 5 币 |

重测答对不能把原任务正确率改成 100%，不能增加原批次 target_count，也不能制造第二条原任务完成记录。个人记忆不会把用户没有在本任务回答过的题自动标成已覆盖。长期任务虽不计奖，真实答案仍能更新个人记忆。

任务结束、计划到期或归档后，推荐继续保留已学记忆并安排复习；用户可暂停复习。创建计划和首次接入时应说明这一点。暂停推荐与删除学习事实分开，用户无需保留一项永不结束的任务才能复习。

**3. 个人记忆的身份与范围**

首期记忆键推荐为：

`user_id + entry_id + pos_id + sense_id + skill + answer_profile`

- `skill` 首期仅 `spelling_zh_to_en`。以后听辨、识义、语境运用各有自己的状态，不从一次拼写答对推断全面掌握。
- `answer_profile` 首期采用当前 `BrE`／`AmE`。同一义项跨词单共用状态；不同英美拼写档案先不自动继承，避免把掌握 colour 当作已经验证 color。切回原档案可继续使用其记录；不新造内容实体。
- `publication_id`、词单 ID、任务 ID、题目 ID不进入记忆键。它们是证据或来源，不应使普通重发布、换任务变成新词。
- CEFR 是出题条件和证据字段，不单独制造一个“学过次数”；实际题面或答案条件变更仍走下面的内容签名规则。
- 只有发生有效作答的语义单元才建立新记忆，不因收藏一本 1000 词的词单就生成 1000 条待复习记录。
- 例子：词单 A 与 B 的“bank：银行”共享状态；“bank：河岸”是另一个义项，单独记录。B 的固定覆盖任务仍需按自身规则作答，但这次作答可更新同一记忆。

首期不向用户显示“掌握 92%”或“永久掌握”。使用“学习中／复习中／待巩固”，并展示最近首次作答、最近间隔复习结果与下次时间。暂停和来源不可用是另外的属性，不伪装成学习程度。

**4. 内容版本与访问权**

记忆保存用户表现，不授予内容权限。新复习题只从当前可访问来源和当前有效词条发布生成。

每条记忆关联用户已实际使用、或在新任务中明确选择并验证过的来源。关联至少记录词单、成员身份、公开代次等；既有任务中的有效首答可以增加来源，用户打开新词单任务时也可为已有记忆登记经验证的来源。不能为了恢复一个词，自动扫描、订阅用户没有选择过的任意公开词单。

| 变化 | 推荐行为 |
| --- | --- |
| A 来源失效，B 是已登记且当前有效来源 | 从 B 重新签发新复习题，保留同一语义的记忆；原来绑定 A 的未答题仍按原权限失效，不悄悄改绑 |
| 所有已登记来源失效 | 保留个人状态，暂停出题；只显示不可用数量及允许展示的说明，不泄露旧题面、答案、作者私密信息 |
| 词条强制撤回或归档 | 所有来源都不能绕过；旧快照不可用于新练习 |
| 来源删除后重建、词条归档后恢复 | 旧未答题不复活；明确重新选择有效来源、校验新代次后可生成新题 |
| 原任务有合法删除宽限期 | 只对该已开始任务生效；不能据此创建新的复习会话 |
| 暂停复习 | 保留状态和历史；正式任务仍可记录表现，但不自动取消用户的暂停选择 |

为避免把后台语义改写误当作同一个记忆，增加服务端 `content_signature` 与 `memory_epoch`：

- 签名覆盖实际选用的题面、规范化答案集合、语义身份、能力、答案档案及影响判题的版本；不包含词单、任务、普通发布 ID或无关展示样式。答案集合规范排序，避免仅顺序改变就重置。
- 同身份且签名不变：普通重发延续状态。
- 实际题面或答案条件改变：首期保守地进入新 epoch，重新验证，保留旧证据；不声称能自动判断改动是否只是纠错。只有无关例句、展示格式等变化，不影响本题型签名时才继续复用。
- 旧活跃任务仍按旧快照判分并按原规则完成，但旧签名证据不得覆盖已经进入新 epoch 的记忆。返回的原任务接口不变，新记忆界面可解释“内容已更新，待重新验证”。
- 跨词性迁移、义项拆并出现新 ID，首期按新对象处理。将来确需继承时，增加明确的人工旧新映射，不在首期做语义相似度推断。
- 校验在签发和接受复习答案时批量完成，不在每次发布时同步扫描所有学过的用户。某个用户未再打开相关功能前，不承诺立即刷新其全部个人提醒。

**5. 首期调度：可解释的间隔，不宣称精确记忆概率**

建议首期使用版本化的分阶段规则 `memory_ladder_v1`，间隔为 **1、3、7、14、30、60、90 天**，到 90 天后维持上限。一次错误进入待巩固，短测通过后从 1 天重新验证。它能先验证完整闭环，代价是个性化程度有限；这些参数是试行默认值，尚无本产品学习效果证据。以后可用积累的间隔、首次结果和内容版本数据评估其他调度算法，但首期不预建通用算法平台。

所有 due_at 为服务端 UTC 时间；界面按用户日期展示。一天间隔表示至少经过 24 小时，不是跨过 04:00 就算一天。

| 输入事实 | 记忆变化 | 下次安排 |
| --- | --- | --- |
| 新单元首次有效答对 | 学习中，间隔第 0 档 | 接受时间 +1 天 |
| 新单元首次有效答错 | 待巩固，错误事件保留 | 接受时间 +10 分钟，可进入短测 |
| 正常学习／复习阶段，到期后未提示的首次答对 | 前进一档，进入或保持复习中 | 从实际接受时间计算下一档间隔 |
| 未到期时在另一项任务再次答对 | 保存练习证据，不前进档位、不推迟既定 due_at | 保持原安排 |
| 当前 epoch 且参与调度的合法首次答错 | 进入待巩固；一次错误阶段只算一次遗忘事件；过期并发证据除外 | 10 分钟后可重测，系统短测受预算限制 |
| 待巩固阶段，间隔至少10分钟后的无提示成功，包括来自正式任务 | 结束当前待巩固阶段，回到学习中 | 接受时间 +1 天；不跳到原来的 30／60 天 |
| 短测仍错 | 保持待巩固 | 可用预算内再等 10 分钟；预算用完移到下一业务日且至少距本次错误 10 分钟 |
| 超期多天后答对 | 只推进一档 | 从本次实际时间计算，不一次跳多档 |
| 内容签名已变化 | 旧 epoch 留存，新 epoch 重新验证 | 重新进入学习／巩固流程 |
| 同请求重放 | 不新增证据、不推进、不改 due_at | 返回同一结果并重新投影当前权限 |

状态转移先看当前阶段，再看入口：只有正常学习／复习阶段的到期成功才推进阶梯；待巩固阶段的合格成功一律回到1天验证。“合格成功”可以来自独立复习，也可以来自当前正式任务，前提是签名和 epoch 一致、通过对应时间门槛、没有服务端已知的提示影响。系统短测次数预算用于限制自动安排，不禁止用户完成另一项已有任务；该任务在10分钟后得到的无提示首答成功可结束待巩固，但不会突破1天规则。它不会倒过来替其他任务完成覆盖。

正确与错误证据都保留。短时间连续答对不增长长间隔；连续答错不会将 due_at 一直向后拖延来逃避复习。进入同一次待巩固阶段后，重复失败按原短测安排和预算合并处理。

首期只把当前规范下的首次答案视为可用证据，不改成让用户自报“简单／困难”。它不是防作弊证明：系统无法知道用户是否在另一个页面查了答案，也不把鼠标停留时长当掌握证据。

**6. 错题重测与提示隔离**

推荐流程为：原题首次提交 → 显示错误与正确拼写 → 用户继续原任务 → 至少 10 分钟后可进入“待巩固”短测。短测是新 attempt，不覆盖原首次答案，不阻塞原任务完成。

- 不要求用户立即照抄正确答案才能前进；刚看答案就输入正确没有足够的长期记忆证据。
- 每个语义单元／能力／答案档案，每业务日最多签发2次系统短测机会。签发时在记忆锁内消耗当日预算，机会带有业务日和序号；同一记忆最多保留一个未结束短测机会。原键重试、双设备和新会话重复请求只恢复同一题目／会话，不再占用预算或另建重复短测。
- 短测机会截止于会话24小时有效期与下一次04:00的较早者。放弃或过期不退回签发预算，避免反复开关绕过上限；新的业务日可以重新签发。已成功答案跨日原键重放仍返回原事实，不重新占用新日预算。
- 一次短测会话只放入已经符合时间条件的项；未到时间可以显示“稍后可重测”，不让用户在页面空等。预算耗尽时系统当天不再安排该项短测；不阻止用户继续已有的正式任务。
- 新复习界面提供“查看答案”时，先向服务端记录提示使用；本题之后答对也只算辅助练习，不推进长间隔。反馈中的标准答案只能在有权且已答／明确揭示后返回。
- 首次错误后，系统已知用户看到反馈；这段至少 10 分钟的窗口内，在其他任务答对同一单元也不能推进长间隔。
- 旧任务界面可能在重开记录时显示已答反馈，但旧客户端没有精确的查看事件。因此兼容期只能保守使用首次答案与接受时间，不能宣称完全识别所有“刚看过答案”的情况；新客户端的提示事件逐步补齐。
- 暂停一天不清空错题。待巩固保存在服务端，由下一次访问恢复。

例子：10 题答对 7 题，任务结果仍是“已完成，正确率 70%”，另显示“3 项待巩固”。其中 2 项短测答对后，显示“本次巩固 2 项”，原正确率、题量、奖励去重数都不改写。

**7. 到期队列与使用体验**

首期增加独立“今日复习”入口，不把复习题混入已经承诺固定题量的每日任务。首页同时显示“待巩固、已到期、稍后到期、原任务待完成”，不把这些数字相加成一个模糊的掌握数。

推荐每批最多 20 个不同单元，可提前退出，已提交立即保存。未到期的内容不为了凑满 20 个强行加入；没有到期内容时明确显示暂时无需复习。首次独立复习只从已经建立记忆的单元取题，不会主动引入新词。

选取规则：

1. 只选当前答案档案下、未被用户暂停、具备当前合法来源、due_at 不晚于服务端时间的项。
2. 已可重测的待巩固项优先，但每批最多占 10 个位置；其余位置给普通到期项，防止错题长期饿死正常复习。某一类不足时，由另一类补足。
3. 每类按 due_at、稳定 ID 排序；不使用需要扫描全部历史的复杂分数。
4. 同一单元在该批只出现一次。答错进入后续符合时间条件的新批次，不把当前批次长度无限拉长。
5. 大量积压时每次仍只提供一个有限批次，并显示剩余数量；不自动扩大已有任务，不因“没清空复习”撤销已完成任务。

调度不依赖为每个用户创建定时任务。到期时间存于数据库，用户访问时查询索引即可；提醒推送、短信和后台自动开练不在首期范围内。

同一天同一个义项从不同入口多次出现，任务事实各自按原规则记录，记忆只按有效间隔推进。一个正式任务的有效到期回答已推进记忆后，下一次独立复习查询不再把它列为到期。

**8. 奖励兼容与明确取舍**

**已确认首期规则：保持既有奖励政策，独立到期复习和错题重测暂不计奖。** 两者不增加每日奖励去重单元数，不触发每日学习奖励、钱包恢复再结算或邀请奖励；不修改账本、既有完成记录及历史收益。复习界面显示记忆变化和下次安排，不显示金币进度增长、领取入口或计奖承诺。

| 行为 | 任务覆盖／正确率 | 个人记忆 | 首期每日奖励 |
| --- | --- | --- | --- |
| 每日任务有效首次答案 | 按原规则更新 | 更新或记录练习证据 | 仍须所在每日批次完成后，按日去重累计 |
| 长期任务有效首次答案 | 按原规则更新 | 同样更新 | 不计，保持原规则 |
| 独立到期复习首次答案 | 不修改原任务 | 更新 | 不计 |
| 错题短测、看答案后练习 | 不覆盖首次答案 | 巩固，不跳长间隔 | 不计 |
| 未完成的每日批次已答部分 | 已答事实保留 | 可以已有真实记忆变化 | 不因为记忆已更新就提前计奖 |
| 同题同请求重试 | 无重复记录 | 无重复推进 | 无重复金额 |

原奖励不增加正确率门槛：10 个不同单元全错但有效完成，仍按现有政策判断奖励；记忆层则把它们放入待巩固。奖励鼓励完成，记忆反映效果，两者不互相伪造。

维持 Asia/Shanghai 04:00 日界线、同账号日上限、钱包暂停／关闭逻辑、未来日政策生效和账本原子性。钱包恢复后，仍需当日新的每日任务完成触发现有再结算；单纯刷新、重放旧请求、独立复习或短测都不触发。登录奖励独立。邀请奖励仍仅由现有成功学习奖励结算触发，独立复习不生成伪造 completion 来触发邀请。

未来是否让到期复习参与奖励，留待另行提出需求和确认政策，不是首期交付依赖。本期不预建复习奖励资格表、通用计奖分支或新结算来源，也不为未来奖励改造 `trigger_completion_id` 和邀请结算链。

**9. 最小数据模型与模块边界**

在现有模块化单体内增加 `learning_memory` 与 `learning_review` 两个边界，不新增服务、消息中间件或独立数据库。名称为设计建议，实施时匹配代码风格。

| 记录 | 主要字段与约束 | 用途 |
| --- | --- | --- |
| `learning_memories` | 用户＋语义单元＋skill＋answer_profile 唯一；epoch、content_signature、stage、interval_step、due_at、last_evidence_at、last_event_id、revision、paused、短测签发业务日和次数 | 当前可查询状态；一行可被多次作答更新 |
| `learning_memory_sources` | memory_id＋词单身份唯一；当前绑定的成员／公开代次，来源登记时间 | 多来源访问验证；不是永久内容副本 |
| `learning_memory_events` | 唯一 source_kind＋source_id；user、memory、epoch、时间、结果、effect、旧新revision、调度版本、内容签名 | 防重复推进与解释当前状态；普通任务只引用既有 answer_id，不再复制整份题面答案 |
| `learning_review_sessions` | user、mode、固定批次大小、状态、创建／过期时间、开始请求键及哈希 | 有限复习批次与多设备恢复；不关联旧 completion 奖励语义 |
| `learning_review_items` | session、memory、签发的revision／epoch、来源及生命周期代次、题面／答案快照、提示状态、机会类型／有效期；短测含签发业务日和序号，同会话同memory唯一、同memory最多一条活跃短测机会 | 只冻结实际入选的最多20项，不提前生成未来几个月的题；活跃标记在接受／取消／到期检查时原子关闭 |
| `learning_review_attempts` | 每 item 最多一个首次有效答案；用户／请求键唯一，答案、判定、服务端时间、effect | 独立复习和短测事实；不写入旧 learning_answers 来绕过其首次约束 |

调度状态是对证据的投影，不是必须保存全部行为日志才能工作的事件溯源系统。事件只保留解释调度需要的字段。普通任务答案不再复制为另一份完整答案；复习答案才有自己的事实表。

初期索引以 `(user_id, answer_profile, due_at, id)` 过滤未暂停记忆，配合用户／单元唯一索引、来源关联索引和事件唯一约束。查询先取有界候选并批量验证来源，不为一页读取用户全部记忆、全部词单或全部历史。不可用候选不得卡住其他有效到期项，也不得被算成已完成；准确可用计数的实现需用 SQL EXISTS／批量投影，不以未校验的原始 due 数冒充可练数。

**10. 写入、并发和重复提交**

现有正式任务答案在已验证来源、写入唯一答案后，在同一事务内追加轻量 memory event 并更新该单元状态，之后仍走原覆盖、完成和奖励规则。原事务任何部分失败，答案、记忆和相关结算一起回滚；不先返回成功再裸写记忆。缺少可用签名的旧题仍按原规则完成，可记录为不参与当前记忆的旧内容证据，不使旧任务无法使用。

首期采用同步短事务，接受“记忆写入技术故障也会使本次提交失败”的代价；通过原请求键可恢复，不能静默漏记。以后若确实需要降低耦合，应以持久事务事件和可重放投影替换，不能直接 fire-and-forget。

独立复习提交的顺序：校验本人和会话 → 校验来源及撤回代次 → 锁定题目和记忆 → 校验幂等 → 用签发的题面、答案与判题版本判定 → 写唯一 attempt 和 memory event → 更新记忆 → 提交。锁顺序须与已有账户／词单／词条协议对齐，不能产生反向加锁。

- 同 item 原请求键重放返回同一次事实；同键不同答案冲突；不同键不能第二次填写同 item。
- 两台设备对正常到期项拿到同一记忆 revision：先接受的证据可推进；后接受的独立复习仍可记作有效练习事实，但 effect 为 `practice_only_stale`，不再次更新记忆、不覆盖更新后的失败／成功。此处包括后到的错误答案，因此规则表中的失败转移不适用于过期并发证据。返回当前安排并提示该项已在另一处更新。
- 短测采用更严格的单机会规则：两设备恢复同一 item，只有一次首次答案；如果该机会已经被正式任务中的合格成功、内容更新等取代，未提交答案直接返回机会失效，不接收为额外短测。预算在签发时已消耗，不依赖是否更新调度，因此没有通过过期证据绕过次数上限的路径。
- 正式任务之间仍按原规则各自保存首答，记忆事件按服务端提交顺序处理；尚未到期的重复正确不推进。不会要求旧客户端提供新的 memory revision。
- 内容 epoch 不一致的旧题，只更新原任务事实，不覆盖新记忆。当前来源已不可用的未答题则拒绝；重放已接受事实时按当前权限隐藏内容。
- 新复习不复用“把作者、邀请人全加排他锁”的通用入口。它没有奖励写入需求，按既有治理协议使用必要的来源共享锁与学习者／记忆锁；不得制造不同学生之间的公共作者排他热点。正式任务原奖励锁的缩减属于另一个需验证的实现改动，不凭本设计直接删除。

正常到期题随复习会话默认有效24小时，跨04:00仍可提交；接受时间决定记忆变化时间。短测题的有效期独立截到下一次04:00，预算归签发业务日，跨界未提交题失效并由新日重新签发；混合会话中的正常到期题不受影响。未答题过期后重新选取，已答事实不重算。会话有效期和幂等回执有效期不同：在复习明细保留期内可原键重放；到期清理后旧 item 不接受新答案，返回明确已过期，不把相同旧 ID当新题重新发奖或推进。

待确认请求按账号和会话保存在浏览器本地，刷新先从服务器对账再重试；退出／切号清除对应待确认数据，服务端是唯一事实来源。本地缓存只保留有界的待确认请求，不能成为失权内容永久阅读入口。真正离线生成、延迟数日补交和按客户端时间回填不在首期范围。

**11. 接口与前端接入草案**

所有新增接口均在 `/api/v1/me` 下，只读写当前已认证、具学生资格且满足现有学习设置要求的用户。客户端不能指定另一个 user_id、due_at、评分、金币或权威业务日。

| 接口 | 用途与关键约定 |
| --- | --- |
| `GET /memory/overview` | 返回 enabled、server_time、next_day_at、当前答案档案、待巩固／到期／稍后到期／暂停／不可用数量；功能不可用与零待复习分开 |
| `GET /memory/items?filter=due&cursor=…` | 固定上限分页；仅投影当前允许显示的词面、状态和下次安排 |
| `PATCH /memory/items/{id}` | 只允许 paused 与 expected_revision；恢复后重新验证来源和签名 |
| `POST /review-sessions` | mode 为 due／retest，limit 默认20且最大20，开始幂等键；可按一个本人任务来源过滤；由服务端选择项 |
| `GET /review-sessions/{id}` | 恢复批次、题目状态和当前可答题；答案按已答／已揭示和当前权限投影 |
| `POST /review-sessions/{id}/items/{item_id}/reveal` | 持久标记提示使用，再返回允许答案；不计首次正确或奖励 |
| `POST /review-sessions/{id}/answers` | item_id、answer、idempotency_key；返回正确与否、memory_effect、下一安排、批次进度 |

新增 wire 类型继续 snake_case。必须值明确 required，未知时间用明确 nullable；阶段／effect 枚举版本化，答案内容不在初始未答响应泄露。请求非法400或现有422，未认证401，资格403，不属于本人404，版本／请求键／会话或来源状态冲突409，基础设施故障503，语义与当前 ProblemDetails 规范对齐。

这些是新增根类型，不直接复用旧 LearningRun 并塞入新枚举。旧 `LearningTask`、`LearningRun`、`LearningAnswerReceipt`、`LearningRewardDay` 保持既有形状。新前端遇旧后端404或功能关闭，保留原任务流程，显示复习尚未开放，不把接口错误显示成“全部复习完成”。

前端改动集中在学生首页入口、独立复习页面和任务完成后的待巩固入口；`LearningTasks` 的固定题量、首次正确率和奖励组件维持原义。必要状态通过独立 memory API获取，不要求旧答案响应带新字段。后台首期不新增编辑器或奖励设置页。

**12. 历史数据、上线顺序与回退**

首期推荐从用户启用时刻开始收集：现有任务不重建、不补完成、不补金币；现有活跃任务在启用后新增的真实首答可建立记忆。历史完成数量不能直接当成记住的词量，避免首日突然制造几千项到期负担。以后若希望导入历史，应设计一次可解释的基线验证流程，而不是伪造近期成功；本期不做全量回填。

预期迁移为新增表、约束与索引，不重写既有 task/cycle/run 的语义。new memory/source/event/review 数据以 user 为属主，用户物理注销时清理；归档某项任务不级联删除独立个人记忆。独立财务审计沿用原保留规则。

发布步骤仅作为未来实施方案，尚未执行：

1. 迁移与兼容后端先到位，新接口和记忆功能默认关闭；旧接口响应保持不变。
2. 所有接收答案的 API 实例升级后，才按用户分批启用采集；不能新旧后端混写而漏掉部分记忆证据。
3. 发布可降级的新 Web，再小范围启用复习入口。旧 Web仍能继续任务，由新后端记录启用后的答案证据。
4. 对比漏事件、重复推进、到期有效召回、并发、任务完成与账本不变量后扩大范围。

兼容矩阵的预期（尚未运行验证）：

| 组合 | 必须验证 |
| --- | --- |
| 旧 Web＋新 API | 原任务、完成、奖励契约不变；启用用户的首答只额外更新内部记忆 |
| 新 Web＋旧 API | 新接口404安全降级，旧任务可继续 |
| 新 Web＋新 API | 跨词单记忆、短测、到期、权限与恢复闭环成立 |
| 新 schema＋旧 API | 功能关闭时既有路径应可用，但它不会维护新记忆；不能在复习仍开放时直接回退 |

回退优先关闭新复习入口和新会话写入，保留 schema 及已保存数据。若回退到不采集记忆的旧二进制，应记录采集缺口起止时间；重启前按唯一 answer_id补录缺口，或明确把受影响记忆重新验证，不能默默声称仍准确。已有新数据时 down 拒绝删除记忆历史；只有空新表或已获明确数据处置授权时才允许破坏性撤回。

**13. 数据留存与性能约束**

首期避免复制现有任务快照。长期稳定空间主要是“用户真正学过的单元数”，复习会话和事件则随使用增长，需要明确上限。

建议默认只在热库保留最近 180 天独立复习题面、答案及详细事件，期满保留每记忆的当前状态、按月最小汇总和一份调度检查点；个人记忆保留至用户删除或注销。180 天作为本版设计默认值，先有保留配置和安全清理验收，再启用清理任务，不在设计阶段删除任何数据。原正式任务历史与金融审计不受这个新复习保留策略影响，也不假定因此已经解决原有明细增长问题。

短测事件不能影响财务去重。清理会话前必须满足已终止、无活跃题目、无仍需重放的请求，并清除浏览器过期待确认项；新会话使用全新 ID。跨越保留窗口的全量原事件重放不作为首期承诺，算法升级从调度检查点接续并记录版本，不能依赖已删除事件重新训练全部历史。

性能验收要证明：取20项不读取用户全部记忆；一次答案更新固定数量行；同一作者来源下不同用户的复习不争公共作者排他锁；内容更新不做全用户同步迁移；不为未到期单元生成题目记录。指标至少包括队列可用率、每请求SQL数、事务时长、锁等待、p95/p99、事件行增长及热库行宽。

学习效果另外观察：按1／3／7／14天等实际间隔分组的首次正确率、同一错误阶段的再次失败率、到期积压数量和年龄、每次练习耗时与退出率。短测、提示后作答、未到期重复和旧内容证据不混入“间隔复习首次正确率”的分母。仅完成量增加不能证明记忆改善；参数调整保留调度版本，并用真实结果比较，不为提高某个短期正确率而无限缩短间隔。

**14. 必须通过的验收场景**

| 场景 | 预期结果 |
| --- | --- |
| 同一义项分别来自词单A、B | 一份记忆、多来源；两个固定任务各自完成，不自动代答 |
| 同词不同义项／词性 | 独立记忆与独立到期时间 |
| 英美档案切换 | 不误继承不同拼写能力；切回可恢复原档案 |
| 10题全错但有效完成 | 原任务完成、正确率0；仍按原政策计奖；记忆为待巩固 |
| 10题只答9题 | 9条记忆证据可存在；原任务未完成，不提前计奖励 |
| 同日跨任务连续答对同词 | 原任务事实分别保存，记忆不连续跳档 |
| 到期项在正式任务中答对 | 更新同一记忆，下一次独立队列不再出这一到期项 |
| 查看答案后立即答对 | 辅助练习，不作为到期无提示成功，不推进长间隔 |
| 错后10分钟短测答对 | 回到学习中、1天后复习，原正确率和金币不改 |
| 原处30天档，答错后11分钟在另一正式任务答对 | 同样回到1天验证，不进60天档；原任务按自身规则完成 |
| 同词短测连续失败／并发开三个会话 | 每业务日最多签发2次；同一未结束机会恢复同item，不无限循环、不拖累原任务完成 |
| 03:59答对、04:01再做 | 业务日可以改变，但不能因跨日就获得一天间隔证据 |
| 03:59签发短测、04:01首次提交或重放 | 未提交机会已过期；此前已成功的原键重放不消耗新日预算 |
| 迟到30天再复习 | 一次答对只推进一档，下一时间从实际答题时间算 |
| 两设备同item／正常到期不同item同revision | 唯一首次答案；同调度机会至多一次推进，后到证据明确仅练习；短测被取代时拒绝未提交答案 |
| 请求超时、刷新、原键重试 | 恢复原事实，记忆无重复推进；换账号不串待确认请求 |
| A失效、已登记B有效 | 新题可选B；原A未答题不静默换源、不复活 |
| 所有来源不可用／强制撤回 | 隐藏内容并停止新题；保留合法个人状态，无永久副本绕过 |
| 普通重发签名不变／签名改变 | 前者延续；后者新epoch重验；旧题不得覆盖新状态 |
| 钱包暂停、恢复后仅做短测 | 不触发现有补结算；新的每日完成仍按原逻辑处理 |
| 独立复习／短测，无论正确或错误 | 不生成旧completion，不增加每日奖励去重数，不触发每日金币、钱包恢复再结算或邀请奖励；界面不显示计奖进度增长 |
| 原末题结算技术失败 | 答案、记忆、完成、相关奖励一起回滚，原键可重试 |
| 计划归档、到期、用户暂停 | 计划历史不改；个人记忆保留；暂停后不推荐 |
| 用户注销、留存清理 | 个人学习数据按规则清理，账本审计不受破坏；旧item不可重新提交 |
| 新旧端混用 | 与上述兼容矩阵一致；接口失败不显示成无待复习 |
