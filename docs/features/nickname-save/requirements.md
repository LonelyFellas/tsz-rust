- 评估日期：2026-10-02；后端主仓为 `nickname-save-assessment-20261002`，分支 `assess/nickname-save-20261002`。
- 已 fetch 最新远程 main：`4b7df469fdd716c37426a5a2bb998e66c6f57ea3`。
- 前端消费者基线：`d8bac23558d080bd8dc2c693cd6be3ce0bbac40b` 加当前 UI 工作区差异；评估没有修改消费者代码。
- 前端已经发送 `PATCH /api/v1/me`，请求 `{ display_name }`，并期待 `{ user }`。当前 Rust 路由和 OpenAPI 缺失该端点，实际调用为 404。
- 现有 `users.display_name`、`DisplayName::parse`、公开用户资料 DTO 可复用，**不需要数据库迁移**。管理员改昵称已有局部更新，但其权限路径不能直接作为用户本人接口。
- 涉及新 API/DTO、身份校验及前端契约配套，按重档产出本文与 `design.md`；本次只评估，不实施。

## 目标与范围

已登录的 C 端用户能保存自己的昵称，资料页及账户菜单使用返回的最新资料；刷新、重新登录后仍显示已保存昵称。

本期仅修改昵称，不增加头像、手机号/邮箱、密码、身份、学习等级或管理员资料的写权限，不重做资料页样式。头像是独立任务，只约定两种局部更新不能互相覆盖。

## 规则

1. 学生、教师均可修改自己的昵称，使用 Web realm 身份，不需要后台 `users.edit` 权限；匿名、Admin realm、已注销/禁用用户及旧安全版本 token 不能写。
2. 用户身份只能来自有效 token。请求不包含用户 id；其他资料字段、null、缺失或错误类型不能被当作昵称更新接受。
3. 复用当前 Rust DisplayName 规则：先 trim 首尾空白，剩余长度为 1–50 个 Unicode 码点；拒绝 `<`、`>`、剩余控制字符及 Cf 格式字符。
4. 允许中文、普通单码点 emoji、引号、`&` 等已有合法输入，不新增 ASCII-only、昵称唯一、冷却或审核规则；包含 ZWJ 等 Cf 的组合仍按现有规则拒绝。
5. 不改变既有 Unicode 校验顺序，不自动修改历史昵称，不进行额外 NFC/字形规范化。空白归一化与计数由后端权威决定，前端预检应对齐。
6. 普通昵称修改不吊销会话、不改变 security_version，不要求重新登录。
7. 更新只写 display_name 与 updated_at；头像、联系方式、角色、密码、安全版本及学习配置都不受影响。
8. 同昵称重复请求可返回成功与完整资料，适合失败后重试；同一昵称字段并发按数据库成功更新顺序后写生效，不新增版本参数或乐观锁。
9. 响应必须是 `{ user: UserProfile }`，不是仅返回 display_name；保留 id、avatar_url、roles、active_role，phone/email 维持现有缺失时省略语义。
10. 数据库提交成功但响应丢失时，客户端可重试同一请求恢复资料；不承诺所有跨页签/设备实时推送，重新读取 `/auth/me` 获取当前值。

## 前端配合

- 保留 updateProfile 的路径、请求与成功响应形状，保留昵称保存与头像上传的同页互斥。
- 对 `invalid_display_name` 按稳定错误码映射中文，不仅依赖旧英文 detail；空、过长及禁字符提示准确，不把服务故障当作“未开放”。
- DOM maxLength 与 JS length 目前按 UTF-16，Rust 按码点；须对齐计数与提交限制，不能把 50 个普通 emoji 错当 100 个昵称字符。
- JS trim 与 Rust trim 对 BOM/U+0085 有差异：对齐规范化预检并补样例，不修改后端已有规则。共享逻辑放 `@tsz/shared`，不在页面复制多套校验。
- 后端实现后同步 OpenAPI，仅移除 `patch /me` 的 PENDING；头像及其他未实现端点不一并移除。

## 验收

- 本人昵称合法保存、完整回包、store 更新、刷新/重新登录一致；重复同名可重试。
- 空白、51 码点、HTML 标记、Cc/Cf、null、缺字段及越权字段拒绝，旧资料不变；50 码点中文/普通 emoji、引号等边界符合既有规则。
- Web/Admin realm 与注销、禁用、改密竞态有真库测试；更新不触发安全字段变化。
- 与头像局部写、管理员昵称写及账号硬删除并发时，不覆盖其他字段、不重新创建已删除用户。
- 核对当前前端与候选 API、候选前端与旧 API、两端候选及回退组合，不以同批发布代替验证。
- 本次运行现有昵称相关纯逻辑测试，13 个通过；新接口、真库写入与真实联调未实现/未验证。

接口、最小改动、回退与验收命令见 [设计评估](design.md)。
