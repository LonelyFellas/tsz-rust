# 测试资源精确清理

测试资源 purge 只在显式配置 `TEST_RESOURCE_PURGE_ENABLED=true` 且配置了 `TEST_RESOURCES_*` 白名单时开放。请求必须携带 `X-TSZ-Test-Run`，管理员必须属于 `TEST_RESOURCES_ADMIN_IDS`，词条也必须在创建时携带同一批次头并登记到该批次。

```http
POST /api/v1/admin/lexicon-next/test-resources/purge
X-TSZ-Test-Run: codex-accept-20261122-1
Content-Type: application/json

{
  "request_id": "<new-request-uuid>",
  "entry_ids": ["<exact-entry-uuid>"]
}
```

服务端只接受已归档词条，并在删除前锁定词条、发布记录和音频资产，检查拓展词、例句、语法、方言配对及跨批次音频引用。正式存储根目录中的音频会直接拒绝处理，只有 `temporary-tests/<run>/audio/` 下的对象才会进入删除阶段。

清理音频时，测试存储凭据需要能列举对象版本并按版本永久删除。服务端逐个核对对象键，删除全部版本和删除标记，再次列举确认为空后才删除数据库登记。开始清理音频后，词条保持归档，恢复和普通删除会返回 409。列举、删除或复查失败时保留登记，可用相同请求重试。

同一管理员并发提交相同的清理请求时，共用第一次成功的回执。清理会移除目标全部属于本次词条的归档和恢复回执，保留含其他词条的回执以及 purge 自身的幂等记录。

普通词条创建请求不携带 `X-TSZ-Test-Run`，因此不会进入测试批次，也不能被该接口清理。

## 独占例句和正式配音批次

使用新 run 和白名单内的专用管理员。词条、独立例句（含词条保存的 `sentence_changes`）、正式配音、试听的相关写请求都携带同一个 `X-TSZ-Test-Run`。打开 purge 开关后，白名单中的专用管理员不能无头调用这些写入口。需同时具备各业务入口的权限。不要复用已有或已封存的 run，不跨批次共享管理对象，也不要在该批次使用不在本清理范围内的上传、头像或认证材料。

先停止该批次的写入并归档全部测试词条。用同一接口传入 `entry_ids` 和 `sentence_ids` 的完整精确列表；没有相应资源时传 `[]`，无需手动枚举音频。管理独立例句的批次还需 `sentences.access`、`sentences.create`。省略 `sentence_ids` 保留上述仅回收词条的旧用法和回执格式。

```json
{"request_id":"<new-request-uuid>","entry_ids":["<exact-entry-uuid>"],"sentence_ids":["<exact-sentence-uuid>"]}
```

批次模式检查共享草稿、其他词条的历史发布和音频引用，拒绝越界或前缀内发现未登记的对象。专属正式配音包括未绑定、已替换、失败和已中断的记录；不会由普通零引用回收提前删除。封存后拒绝新写入，按登记永久删除全部音频和试听的精确对象版本及删除标记，复查对象为空后清理数据库引用、配音幂等登记与试听缓存/Redis 锁。清理前仍有写入会返回 409，等原写入结束后重试。删除或复查失败保留登记，同一管理员用原请求 ID 和原列表重试；成功后可重放原清理回执。不能改用新 ID 跳过已封存的清理。

该功能不会追补迁移前创建的例句、生成或试听登记。迁移只加批次登记，不改普通资产；回退前须停掉对应客户端并回收所有已登记资源，回退会移除批次终态记录，不能重用这些 run。
