# 新用户英语等级评估系统 · 产品方案

> 背单词产品的新用户定级模块(CEFR A1–C2)。设计思路 = LexTALE 假词防猜 + EF SET 升降档自适应。
> 版本:v0.2(2026-07-18)  状态:待评审
> v0.2:答题交互改为滑卡;重测策略由「7 天冷却」改为「共 3 次机会,以最后一次为准」。

---

## 1. 背景与目标

### 1.1 要解决的问题

背单词产品的核心矛盾:**推送的词太难,用户挫败流失;太简单,用户觉得没用也流失。** 一切个性化推荐的前提是知道用户当前水平。让用户自选等级不可行——语言学习者系统性高估或低估自己,自报等级与实测的偏差普遍在一个大档以上。

### 1.2 产品目标

| 目标 | 衡量方式 |
|---|---|
| 新用户 3 分钟内拿到可信的 CEFR 定级 | 测评中位时长 ≤ 3 min |
| 定级结果直接驱动词书/学习计划推荐 | 定级 → 推荐 → 开始学习一条链路走通 |
| 防止乱点导致的定级失真 | 无效测评率 < 5%,且能被识别出来 |
| 不因测试流失新用户 | 测评完成率 ≥ 85%,提供跳过兜底 |

### 1.3 非目标(本期不做)

- 不测听力、口语、写作——只测词汇识别,词汇量与 CEFR 的相关性足以支撑背单词场景。
- 不做正式的等级证书/报告——结果仅用于产品内推荐。
- 不上 IRT(项目反应理论)——MVP 用升降档状态机,数据积累够了再升级(见 §10)。

## 2. 竞品参考

| 产品 | 可借鉴 | 不适用的原因 |
|---|---|---|
| **EF SET** | 自适应难度、15 分钟出 CEFR 结果、结果页体验好 | 测四项技能,时长对背单词 onboarding 太重 |
| **Duolingo English Test** | IRT 自适应的天花板;题型多样防作弊 | 工程复杂度高,冷启动没有校准数据 |
| **LexTALE**(学术) | **假词防猜**——混入 25% 不存在的词惩罚乱猜;5 分钟;效度经论文验证 | 固定题目不自适应,对高/低水平用户浪费题量 |
| **墨墨 / 百词斩** | 入门词汇量摸底 → 直接转化为词书推荐的产品闭环 | 无防猜机制,自报「认识」系统性偏高 |

**本方案的组合点:LexTALE 的防猜计分 + EF SET 的升降档收敛 + 墨墨式的结果转化闭环。**

## 3. 设计原则

1. **快**:15–30 题,中位 3 分钟。每多一分钟都在流失新用户。
2. **防猜**:用户无法通过乱点「认识」刷高等级(假词误报惩罚)。
3. **保守定级**:边界情况取低档。背单词场景里"内容稍简单"的伤害远小于"内容太难"。
4. **服务端权威**:升降、计分、真假词信息全在后端,客户端拿不到任何可推断答案的字段。
5. **结果即价值**:测完立刻给出词汇量估算 + 词书推荐,让用户感觉"被了解"而不是"被考试"。
6. **可跳过、可重测**:测试是服务不是门槛。

## 4. 用户流程

### 4.1 主流程(新用户 onboarding)

```
注册完成
   │
   ▼
[引导页] "1 分钟测出你的词汇量" ── 跳过 ──▶ 默认 A1 或手动选档(标记为未验证)
   │ 开始测试
   ▼
[答题页] 卡片堆叠,滑卡作答(左滑=认识,右滑=不认识)
   │  · 每 5 题为一块,块间无感知,进度条按预估总题数走
   │  · 15–30 题,升降档自适应
   ▼
[结果页] CEFR 档位 + 词汇量估算区间 + 一句能力描述
   │  · "为你推荐:XX 词书 / 每日 XX 词计划"
   ▼
[学习计划确认] → 进入首次学习
```

### 4.2 分支流程

- **乱点被识破**(假词误报过多):结果页不给等级,文案"这次测试的作答不太稳定,再认真测一次?"→ 重测;拒绝则保守给 A1 并标记 `invalid`。**无效测试不消耗测试机会**。
- **中途退出/断线**:session 保留 24h,回来从当前块继续;超时作废。主动退出不消耗测试机会,退出前弹确认("本次作答不会保存")。
- **重测(3 次机会规则)**:每个用户共 **3 次测试机会(含首测),以最后一次完成的结果为准**——即使新结果更低也覆盖。重测前弹确认告知"新结果将覆盖当前等级,剩余 N 次机会";次数用完后重测入口隐藏,结果锁定。只有拿到定级结果(`completed`)才计一次;无效、退出、跳过均不计。
- **手动改档**:允许,但标记为 `self_reported`,与实测档分开存——后续数据分析要区分。

### 4.3 答题交互细节(滑卡)

- **卡片堆叠 + 滑动作答**:单词以卡片形式呈现,当前卡下压两张缩小半透明的背面卡,滑走一张下面顶上——视觉连续,块边界(每 5 题一次提交)对用户无感。**左滑=认识,右滑=不认识**,与底部按钮位置一致。
- **误滑三层防护**(定级场景每次误答都是噪声,必须兜):
  1. 滑动阈值:拖动距离不足(约 90px)松手即弹回,不算作答;
  2. 方向印章:拖动中卡片上实时渐显「认识/不认识」印章,松手前用户始终清楚这一滑的含义;
  3. 按钮保留:底部「认识 / 不认识」按钮作为备选输入,点按触发同样的飞出动画。
- **动效**:卡片跟手平移带轻微旋转;确认后向对应方向飞出,新卡自下方弹入;遵守系统"减弱动态"设置(降级为瞬时切换)。
- **方向惯例风险**:滑卡产品(Tinder 系)惯例是右滑=积极,与本方案相反;靠方向印章兜住误解,方向在代码中为单一常量,M3 可 A/B 两种方向的误答率后定稿。
- **不显示当前档位、不显示对错反馈**——显示对错会让用户在假词上起疑,也会诱发焦虑。
- 进度显示"第 n / 约 25 题"或纯进度条;块数不固定,文案用"约"。
- 每题记录响应时长 `rt_ms`(第二道防猜防线,MVP 只记录不启用)。

## 6. 词库方案

### 6.1 真词库

- **来源**:Oxford 3000 + Oxford 5000(牛津官方,每词自带 CEFR 标注,可免费获取)。
- **规模**:每档(A1–C2)≥ 60 词,MVP 全库 ~400 词。C2 档 Oxford 5000 覆盖弱,可用 COCA 词频 8000+ 段补充。
- **抽样**:档内按词频三分层(高/中/低频),每块 4 词从三层随机取,避免抽到的全是该档最偏的词;session 内去重。

### 6.2 假词库

- **规模**:80–100 个,不分档。
- **生成**:Wuggy(学术界标准假词生成器)或按英语 bigram/trigram 音位规则生成,如 `mensible`、`purrage`、`kilp`。
- **审核**:人工过一遍,剔除:碰巧是真词/专名/品牌;拼写明显不像英语的;与高频词编辑距离 1 的(如 `worg`——太像 word,会误伤认真用户)。

## 7. 核心算法

### 7.1 出题结构

每**块** 5 题 = 当前档 4 个真词 + 1 个假词,假词位置随机。用户侧题面无任何区别。

### 7.2 升降档状态机(EF SET 部分)

档位索引 A1=0 … C2=5,**起测 A2**。每块只按 4 个真词判定(真词答「认识」=对;假词不参与升降):

| 4 题答对数 | 动作 |
|---|---|
| ≥ 3 | 升一档 |
| = 2 | 到达边界 → 当前档收敛 |
| ≤ 1 | 降一档 |

**收敛规则:**
- 方向反转(升→降 或 降→升)即收敛,取两档中**较低者**;
- C2 块 ≥3 → 定 C2;A1 块 ≤1 → 定 A1;
- 最少 3 块(15 题),最多 6 块(30 题);到上限未收敛取最后两块表现较好的档。

### 7.3 假词防猜计分(LexTALE 部分)

全场假词 3–6 个。误报 = 假词答「认识」。收敛后做最终修正(按 6 假词计):

| 误报数 | 判定 |
|---|---|
| 0–1 | 结果可信 |
| 2 | 最终档 **降一档** |
| ≥ 3 | **无效**,引导重测;拒绝则保守 A1 |

要点:真词答「不认识」不惩罚(正常能力信号);只有假词误报暴露乱猜。另存连续分 `adjusted = 真词命中率 − 误报率` 供后续调参,不参与定档。

### 7.4 档位 → 词汇量映射(结果页展示用)

| 档位 | 词汇量区间(展示口径) |
|---|---|
| A1 | ~500–1,000 |
| A2 | ~1,000–2,000 |
| B1 | ~2,000–3,000 |
| B2 | ~3,000–4,500 |
| C1 | ~4,500–8,000 |
| C2 | 8,000+ |

### 7.5 参数表(集中配置,上线后按数据调)

| 参数 | 初始值 |
|---|---|
| 起始档 | A2 |
| 块大小 / 每块假词 | 5 / 1 |
| 升档线 / 降档线 | 3/4 · 1/4 |
| 最少块 / 最多块 | 3 / 6 |
| 误报无效线 / 降档线 | 3 / 2 |
| session 有效期 | 24h |
| 测试机会(含首测) | 3 次,以最后一次结果为准 |
| 滑动触发阈值 | 90px(不足弹回) |

## 8. 技术设计概要

### 8.1 数据模型

```sql
assessment_words (
  id, text,
  kind      TEXT,   -- 'real' | 'pseudo'
  band      TEXT,   -- 'A1'..'C2',假词 NULL
  freq_rank INT
)

assessment_sessions (
  id, user_id,
  state        TEXT,  -- 'in_progress' | 'completed' | 'invalid' | 'expired'
  current_band TEXT,
  block_no     INT,
  moves        TEXT,  -- 升降历史 "UUD",反转判定用
  result_band  TEXT,
  result_source TEXT, -- 'tested' | 'self_reported' | 'default'
  false_alarms INT,
  started_at, finished_at
)

assessment_items (
  id, session_id, word_id,
  position INT, answered_yes BOOL, rt_ms INT, answered_at
)
```

### 8.2 API(服务端权威,整块提交)

```
POST /api/v1/assessments
  → 201 { session_id, block: [{ item_id, text }] }
  → 403 { error: "quota_exhausted" }        -- 3 次机会已用完

POST /api/v1/assessments/{id}/answers
  body { answers: [{ item_id, known, rt_ms }] }
  → 200 { next_block: [...] }                      -- 继续
  → 200 { result: { band, vocab_range, state } }    -- 收敛
  → 200 { result: { state: "invalid", reason } }    -- 乱点

GET  /api/v1/assessments/{id}                       -- 断线恢复
```

响应中**永不包含** `kind`、`band`、对错信息。状态机实现为不碰 DB 的纯函数,便于单测全覆盖。

**次数控制在服务端强制**:已用次数 = 该用户 `state = 'completed'` 的 session 计数(`invalid` / `expired` 不计),创建 session 时校验,不信任前端传来的任何计数。用户当前等级 = 最近一次 `completed` session 的 `result_band`(天然实现"以最后一次为准",无需额外字段)。

## 9. 数据指标与校准

### 9.1 过程指标(测评本身健康度)

- 测评开始率(引导页 → 开始)、完成率(目标 ≥85%)、逐块流失分布;
- 中位时长(目标 ≤3 min)、无效率(目标 <5%);
- 定级分布:预期近似正态、众数落在 A2–B1(中文用户);若 C1+ 占比异常高 → 防猜失效或词库偏易。

### 9.2 效果校准(定级准不准的真值信号)

**首周学习回流验证**:被定级用户在学习推荐词书时,初见词的「认识」率应落在 **60–80%** 的甜蜜区间——

- 显著 <60%:定级系统性偏高 → 调升档线或加严误报惩罚;
- 显著 >80%:定级偏低 → 放宽;

这是免费的持续校准信号,比再造一套人工标注便宜得多。上线即埋点。

### 9.3 A/B 预留

起始档(A2 vs B1)、块大小(5 vs 6)、滑动方向(左滑=认识 vs 右滑=认识,看两方向误答率)、结果页文案对"开始学习"转化率的影响。

## 10. 里程碑

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| **M1 · MVP** | 词库导入(400 真词 + 80 假词)、状态机、3 个 API、基础结果页、跳过兜底 | 内部自测:5 名不同水平的人定级符合预期 |
| **M2 · 闭环** | 结果 → 词书推荐打通;埋点齐全;断线恢复;重测入口 | 完成率 ≥85%,无效率 <5% |
| **M3 · 校准** | 首周回流验证看板;按数据调参数表;词库扩到每档 100+ | 初见词认识率进入 60–80% 区间 |
| **M4 · 进阶(可选)** | 作答数据积累后上 2PL IRT 逐题自适应;题型扩展(词义四选一混入) | 与状态机版 AB 对比定级稳定性 |

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 用户从社区得知"有假词"后策略性全答不认识 | 全答「不认识」只会定到 A1,对用户自身无收益;真词答「不认识」不惩罚的设计本身不可被利用 |
| Oxford 词表 C2 段覆盖不足 | 用 COCA/BNC 高频段(8000+)补充,人工核 CEFR 归档 |
| 假词质量差误伤认真用户 | 人工审核 + 上线后监控单个假词的误报率,异常高的(>40%)说明太像真词,下架 |
| 4 题/块噪声大导致误判档位 | 保守收敛(取低档)兜底;M3 用回流数据校准;必要时块加大到 6 |
| 滑卡误操作引入定级噪声 | 滑动阈值弹回 + 方向印章渐显 + 按钮备选;监控左右方向误答率差异 |
| 3 次机会用完后定级仍不准 | 首周回流验证(§9.2)发现明显失准时,由系统主动发放一次额外测试机会,而非用户自助重测 |
| 新用户嫌麻烦直接流失 | 引导页强调"1 分钟";可跳过;进度条给确定感 |
| 词表版权 | Oxford 3000/5000 词表本身可免费使用,但释义/例句需自备(词典 API 或开源词库) |
